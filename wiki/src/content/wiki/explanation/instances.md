## 两层模型

GoDoIt 把用户选择和二进制内容分开保存。

- **资产层**保存在 `engines/` 和 `sdks/`。引擎和 SDK 由底层安装流程校验、发布和卸载，可以被多个条目共享。
- **条目层**保存在 `instances/*.toml`。条目引用资产，并带有 SDK 策略和环境配置。它不复制二进制内容。

```
engines/4.5.2-standard/        # 一份引擎资产
instances/<uuid>.toml          # 引用这份资产（显示名"工作"）
instances/<uuid>.toml          # 也可以引用同一份资产（显示名"游戏"）
```

条目文件名是 gdit 生成的 UUID v4 存储标识，显示名（可中文）存放在文件内：用户用显示名寻址
（`gdit run 工作`），内部一律以 UUID 为准（current 链接、引用扫描、GC）。显示名是 URL 安全
字符集（ASCII 只允许 `[A-Za-z0-9._~-]`，非 ASCII 文字允许），全仓库唯一，不与版本号或资产
ID 互相排斥。

## 引用关系是派生的

GoDoIt 不维护单独的引用计数文件。需要检查引用时，它会重新扫描 `instances/*.toml`，再与已安装资产比较。条目文件因此是引用关系的事实来源。

扫描必须读完所有候选条目。只要其中一个文件无法读取、解析或通过校验，删除资产的操作就会停止。修复条目以后才能重新计算引用。

## 孤儿资产与 autoremove

删除条目以后，没有任何条目引用的引擎或 SDK 会成为孤儿。GoDoIt 会保留它们，并通过两个步骤让用户决定是否清理。

1. `gdit remove` 完成后列出新的孤儿及占用空间。
2. `gdit autoremove` 获得确认后，在锁内重新扫描并删除仍然没有引用的资产。

重新扫描处理了确认期间引用发生变化的情况。如果另一个进程创建了新条目并引用某项资产，这项资产不会进入实际删除结果。

## 条目不可变的部分

条目创建以后，`[engine]` 引用保持不变。需要更换引擎版本时，创建另一个条目。`[env]` 可以通过 `gdit env` 修改。当前阶段没有专门修改 `[dotnet]` 策略的命令，需要手动编辑条目或重建条目。
